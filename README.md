# News Aggregator — агрегатор новостей

Сервис автоматически собирает материалы из нескольких RSS-источников, сохраняет их в
SQLite с дедупликацией и раз в 2 сбора отправляет дайджест в Telegram.

**Сценарий:** `Источники → Сборщик → База данных → Фильтрация → Дайджест → Пользователь`

## Возможности

- сбор из **двух и более источников** (реестр источников расширяемый);
- **SQLite** с дедупликацией: `UNIQUE(url)` + `UNIQUE(title, source)`;
- **автоматический запуск** через APScheduler: сбор каждые 30 минут;
- **дайджест каждые 2 сбора**: окно = последние 2 сбора, топ **1–3 новости
  с каждого источника**, общий лимит настраивается, без повторов;
- отправка в **Telegram** (Bot API) с fallback в консоль, если токен не настроен;
- **FastAPI**: просмотр собранных данных, ручной запуск сбора/дайджеста;
- лог работы сборщика в файл `collector.log`.

## Стек

Python 3.12+, httpx, feedparser, SQLite, APScheduler, FastAPI, uvicorn, python-dotenv.

## Установка и запуск

1. Склонируйте репозиторий:

```bash
git clone <url-репозитория> news
cd news
```

2. Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux/macOS
pip install -r requirements.txt
```

3. Настройте конфигурацию:

```bash
copy .env.example .env          # Windows
# cp .env.example .env          # Linux/macOS
```

Заполните `TELEGRAM_BOT_TOKEN` (токен от @BotFather) — без него дайджест
печатается в консоль.

4. **Основной режим** — API + планировщик в одном процессе:

```bash
python main.py                  # http://127.0.0.1:8000, планировщик активен
```

**Только планировщик** (без веб-интерфейса):

```bash
python main.py --no-api
```

**Ручные команды** (отладка; сервис работает и без них):

```bash
python -m bot.cli collect   # собрать данные из всех источников сейчас
python -m bot.cli digest    # сформировать и отправить дайджест
python -m bot.cli stats     # статистика базы
python -m bot.cli chat-id   # узнать TELEGRAM_CHAT_ID для .env
python -m bot.cli bot       # запустить только Telegram-поллер (без API/планировщика)
```

При первом запуске на пустой базе выполняется автоматический сбор.

## Настройка (.env)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather | — (без него дайджест печатается в консоль) |
| `TELEGRAM_CHAT_ID` | ID чата/пользователя | — |
| `COLLECT_INTERVAL_MIN` | период сбора, минут | `30` |
| `DIGEST_EVERY_N_COLLECTS` | дайджест после каждого N-го сбора (`0` — по времени ниже) | `2` |
| `DIGEST_HOUR` / `DIGEST_MINUTE` | время дайджеста, если `DIGEST_EVERY_N_COLLECTS=0` | `9:00` |
| `DIGEST_MIN_PER_SOURCE` | минимум новостей с источника в дайджесте | `1` |
| `DIGEST_MAX_PER_SOURCE` | максимум новостей с источника в дайджесте | `3` |
| `DIGEST_MAX_ITEMS` | общий лимит новостей в одном дайджесте | `30` |
| `DIGEST_FROM_HOUR` / `DIGEST_UNTIL_HOUR` | окно отсылки дайджеста, `0-0` — круглосуточно | `8` / `23` |
| `TIMEZONE` | часовой пояс расписания (IANA, напр. `Europe/Moscow`) | `UTC` |
| `DB_PATH` | файл базы | `news.db` |
| `LOG_FILE` | файл лога | `collector.log` |

### Как получить TELEGRAM_CHAT_ID

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен → `TELEGRAM_BOT_TOKEN` в `.env`.
2. Напишите боту любое сообщение (например `/start`).
3. Выполните:

```bash
python -m bot.cli chat-id
```

Команда покажет `chat_id` и строку для `.env`. То же самое — вручную:
`https://api.telegram.org/bot<TOKEN>/getUpdates` → `result[].message.chat.id`.
Для группы: добавьте бота в чат, напишите сообщение — id будет отрицательным (с префиксом `-100`).

## Управление ботом

Кнопки и команды в Telegram. Поллер запускается автоматически вместе с сервисом
(токен задан в `TELEGRAM_BOT_TOKEN`).

| Кнопка / команда | Что делает |
|---|---|
| `/start` | главное меню |
| `📥 Дайджест сейчас` (`/digest`) | отправить накопленный буфер и очистить его |
| `📥 Дайджест: источник` | сводку по конкретному источнику; показанное убирается из буфера |
| `⚙️ Настройки` (`/settings`) | диалог: интервал сбора, дайджест после N сборов, окно отсылки |
| `📊 Статус` (`/stats`) | статистика и текущие настройки |
| `/cancel` | отменить активный диалог настройки |

**Диалог настройки**: нажатие кнопки выводит текущее значение, пример записи и лимиты,
после чего ждёт ввода текстом. Невалидные значения отклоняются с пояснением.

- интервал сбора: целое от `5` до `180` минут, пример `15`;
- дайджест после N сборов: целое от `1` до `12`, пример `2`;
- окно отсылки: `ЧЧ-ЧЧ` (пример `9-21`), `0-0` — круглосуточно; часы от `0` до `23`,
  начало не должно совпадать с концом. Работает через `DIGEST_FROM_HOUR`/`DIGEST_UNTIL_HOUR`.

Пример:

```
/start → ⚙️ Настройки → 🔁 Интервал сбора новостей → вводите: 15
✅ Интервал сбора новостей сохранено: 15 мин
```

## База данных

Файл: **`news.db`** (SQLite, создаётся автоматически при первом запуске;
путь задаётся `DB_PATH`). Схема — `database/db.py`.

```sql
CREATE TABLE items (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    title       TEXT NOT NULL,
    url         TEXT NOT NULL,
    source      TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    created_at  TEXT NOT NULL,
    is_read     INTEGER NOT NULL DEFAULT 0,   -- отправлен ли материал
    run_id      INTEGER NOT NULL DEFAULT 0,   -- номер сбора
    UNIQUE (url)
);
```

Обязательные поля ТЗ: `id, title, url, source, description, created_at`.
Служебные: `is_read`, `run_id` — учёт отправленного и окна дайджеста.
Дополнительные таблицы: `collections` (история сборов), `meta` (маркер
последнего дайджеста).

Посмотреть содержимое: `python -m bot.cli stats`, API `GET /stats`
или любой SQLite-браузер (DB Browser for SQLite, расширение VS Code).

## Дедупликация

1. **Уровень СУБД:** `UNIQUE(url)` и `UNIQUE(title, source)` в таблице `items`,
   вставка через `INSERT` с обработкой `IntegrityError`.
2. **Уровень приложения:** перед вставкой выполняется проверка
   `WHERE url = ? OR (title = ? AND source = ?)`.
3. **Внутри дайджеста:** выборка дополнительно чистится по URL
   (`bot.digest.dedup_rows`) — одна и та же новость не попадёт дважды.
4. **Между дайджестами:** окно ограничено маркером `last_digest_run_id`
   (таблица `meta`), отправленные материалы помечаются `is_read = 1` —
   повторно в сводку они не вернутся. Новость, увиденная в двух сборах,
   хранится одной записью (привязана к первому сбору).

Повторный сбор тех же лент не создаёт дубликатов (см. лог: «пропущено дубликатов»).

## Как это работает

1. **каждые 30 минут** (`COLLECT_INTERVAL_MIN`) задача `job_collect` обходит все
   источники и сохраняет новые элементы в SQLite — это один **сбор**
   (запись в таблице `collections`, элементы получают `run_id`);
2. после **каждого 2-го сбора** (`DIGEST_EVERY_N_COLLECTS`) автоматически
   формируется дайджест: **окно = эти 2 сбора** (всё, что собрано после
   прошлого дайджеста);
3. из окна отбирается **топ 1–3 новости с каждого источника**
   (свежие сверху), пока не наберётся `DIGEST_MAX_ITEMS`; лишние
   отсекаются, минимум 1 на источник сохраняется;
4. текст отправляется в Telegram, **всё окно** помечается обработанным,
   маркер `last_digest_run_id` сдвигается — материал не повторится
   в следующих дайджестах;
5. при `DIGEST_EVERY_N_COLLECTS=0` включается резервный режим:
   дайджест по времени `DIGEST_HOUR:DIGEST_MINUTE`;
6. при остановке `Ctrl+C` процесс завершается корректно.
